# 재난 알림 RAG 문서

Spring AI 가 알림 문장을 쓸 때 읽는 근거 문서. 인북천 물빛테마공원 캠핑장 1곳 기준.
(서버에 붙일 때 `server/src/main/resources/` 아래로 옮길 예정. 위치는 서버 설계 때 정함)

## 원칙
- 화면에는 판단 한 줄 + 갈 곳 + 길안내만 보인다 (괜찮음 / 준비 / 대피 / 즉시 대피)
- 단계는 서버 코드가 강수량으로 정한다. AI 는 단계를 정하지 않는다
- AI 는 정해진 단계의 문서를 읽고 안내 문장만 쓴다. 문서에 없는 숫자·장소를 만들지 않는다
- 높이(REM)·면적 비율 같은 숫자는 판단 근거로만 쓰고 화면 문장에는 넣지 않는다

## 파일
| 파일 | type | 내용 |
|---|---|---|
| 00_캠핑장_기본정보.md | place | 캠핑장 높이, 대피할 곳 2곳, 쓰지 않는 대피소, 공통 행동 |
| 01_안전.md | level 0 | 괜찮음 |
| 02_주의.md | level 1 | 준비 (호우주의보: 3시간 60 · 12시간 110mm) |
| 03_경보.md | level 2 | 대피 (호우경보: 3시간 90 · 12시간 180mm) |
| 04_범람.md | level 3 | 즉시 대피 (50년에 한 번 큰비: 3시간 114 · 24시간 310mm) |
| 05_출처와_한계.md | source | 출처, 한계 |

문서 하나 = 조각(chunk) 하나. 단계 문서가 둘로 잘리면 할 일과 갈 곳이 따로 검색될 수 있어서 문서를 짧게 유지한다.

## 단계 문서 모양 (모두 같은 순서)
```
---
id / type / level / decision     ← 메타데이터. 검색할 때 level 로 바로 찾는다
---
## 판단            화면 한 줄
## 이 단계가 되는 조건
## 할 일            3개 이내
## 안내할 곳
## 하지 말 것
## 근거            사용자 화면에는 안 보임
```

## 알림을 만드는 흐름 (서버 설계 전 초안)
1. 코드: 강수량 → 단계(level) 결정
2. 검색: `level` 이 같은 단계 문서 + 00_캠핑장_기본정보 를 메타데이터로 가져온다 (유사도 검색이 아니라 정확히 찾기)
3. AI: 두 문서만 보고 2~3문장 안내문 작성
4. 화면: 판단 한 줄(문서의 "판단")은 코드가 그대로 넣고, AI 문장은 그 아래 보조 설명으로 쓴다
