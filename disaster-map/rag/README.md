# 재난 알림 RAG 문서 (인북천 물빛테마공원 캠핑장)

AI가 재난 알림 문장을 쓸 때 읽는 근거 문서다. 2026-11-27 기준 앱(main) 값에 맞췄다.
예전 `safecamping/disaster-map/rag/`를 이어받았다. 바뀐 점은 맨 아래에 있다.

## 원칙 (AI가 꼭 지킬 것)
1. **단계는 AI가 정하지 않는다.** 서버 코드(`DisasterRules`)가 비·상류 수위·호우특보 중 가장 높은 쪽으로 정한다. AI는 받은 단계를 그대로 쓴다.
2. **문서에 없는 숫자·장소·길을 만들지 않는다.** 모르면 쓰지 않는다.
3. **할 일이 먼저다.** 첫 문장은 "지금 무엇을 하라"이다. 비의 양 같은 숫자는 그 뒤에 쓴다.
4. 높은 곳 길은 현장 확인 전이다. **"가까운 높은 곳"**이라고만 쓴다. 방향·거리·시간을 단정하지 않는다.
5. 예시(시연) 특보면 문장 맨 앞에 **"[예시]"**를 붙인다.
6. 기상청 특보·현장 안내와 다르면 그쪽을 따르라고 안내할 수 있다.

## 알림을 만드는 흐름
```
① 서버: 10분마다 비·반월촌교 수위·인제 호우특보 확인 → 단계(level 0~3)와 까닭(reasons) 결정
② 단계가 올라가면 알림 대상 (05_알림_보내는_법.md 의 "언제 보내나")
③ 검색: level 이 같은 단계 문서 1개 + 00_캠핑장_기본정보 + 05_알림_보내는_법 을 메타데이터로 정확히 가져온다
   (유사도 검색이 아니라 level·type 으로 찾기. 까닭 설명이 필요하면 06_단계_까닭 도 함께)
④ AI: 문서만 보고 제목 1줄 + 본문 2~3문장 작성 (형식은 05)
⑤ 앱: 제목·본문을 푸시로 보내고, 누르면 재난지도(/app/disaster)로 이동
```

## AI에게 넘기는 값 (서버 → AI)
| 칸 | 예 | 설명 |
|---|---|---|
| level | 2 | 0 안전 · 1 준비 · 2 대피 · 3 대피(침수) |
| prevLevel | 1 | 직전 단계. 오를 때만 보낸다 |
| reasons | ["인제 호우경보 발효"] | 서버가 만든 까닭 문장 (06 참고) |
| rain3h | 95 | 최근 3시간 비(mm). 모르면 null |
| warnings | ["호우경보"] | 인제에 발효 중인 특보 이름 |
| demo | false | true 면 시연용 예시 → "[예시]" 붙이기 |

## 파일
| 파일 | type | level | 내용 |
|---|---|---|---|
| 00_캠핑장_기본정보.md | place | - | 위치, 높이, 대피할 곳 2곳, 쓰지 않는 대피소, 공통 행동 |
| 01_안전.md | level | 0 | 안전 |
| 02_준비.md | level | 1 | 준비 (호우주의보 기준) |
| 03_대피.md | level | 2 | 대피 (호우경보 기준) |
| 04_침수.md | level | 3 | 대피 · 캠핑장 잠김 (50년 빈도 큰비) |
| 05_알림_보내는_법.md | notify | - | 언제 보내나, 문장 형식, 하지 말 것, 예시 |
| 06_단계_까닭.md | reason | - | 서버 까닭 문장 읽는 법 (비·수위·특보) |
| 07_출처와_한계.md | source | - | 출처, 한계 |
| chunks.jsonl | - | - | 위 문서 8개를 조각 8개로 (DB에 넣는 용) |

문서 하나가 조각 하나다. 단계 문서가 둘로 잘리면 할 일과 갈 곳이 따로 검색될 수 있어서 문서를 짧게 유지한다.

## 단계 문서 모양 (모두 같은 순서)
```
---
id / type / level / name        ← 메타데이터. level 로 바로 찾는다
---
## 판단            화면 첫 줄 (앱 LV.head 와 같은 문장)
## 이 단계가 되는 조건
## 할 일            3개 (앱 "○○ 단계 행동요령" 과 같은 문장)
## 안내할 곳
## 하지 말 것
## 알림 예시        AI가 참고할 문장 (그대로 베끼지 않아도 됨)
## 근거            사용자 화면에는 안 보임
```
