# 작업 기록 (Claude 채팅에서 진행한 내용 요약)

이 문서는 Claude 채팅에서 함께 작업한 내용을 Claude Code가 이어받을 수 있게 정리한 거예요.
새 작업을 시작하기 전에 CLAUDE.md와 이 문서를 먼저 읽어 주세요.

## 1. 프로젝트 배경

- 팀 "캠핀(CAMPIN)", 공간정보아카데미 3조. 사용자는 2부 **메타버스 안전교육** 담당이고, 팀에서는 DB 관리자 역할.
- 대상: **인북천 물빛테마공원 캠핑장** (강원 인제군 서화면 천도양지길 14-57). 처음엔 백담계곡오토캠핑장이었다가 바뀜.
- 목표: 가족·어린이가 3D 캠핑장을 돌아다니며 위험 지점을 찾고 퀴즈를 푸는 웹 게임. 실사 디지털 트윈이 아니라 **게임풍 로우폴리** 스타일.
- 교육용이라 실제 크기·위치가 정확할 필요는 없음 (10~20m 오차 허용). 순서·방향·강 위치만 맞으면 됨.
- 사용자는 개발 초보. 설명은 **한국어로 쉽게**, 바꾼 이유를 함께 설명해 주길 원함.

## 3. 정한 것 (결정 사항)

- 날씨: **기상청 API를 쓰지 않고 무작위**로. 판마다 맑음·비·강풍·폭염 중 하나, 탐험 중 1~2번 바뀜. (비가 오면 강이 불어나는 기능은 2026-11-18에 보류. 아래 8번 참고)
- 퀴즈: **PostgreSQL**에 `quiz` + `quiz_choice`(보기 분리, 정규화) 테이블로 저장하고 DB에서 가져옴. SQL은 `sql/` 폴더(01 생성, 02 13문제 입력, 03 조회). Spring Boot `GET /api/quizzes`가 missions.json과 같은 JSON 모양으로 응답. 서버가 꺼지면 `public/data/missions.json` 예비 파일 사용.
- 게임 기록: 처음엔 저장 안 하기로 했다가 → **나중에 타임어택(문제 푸는 데 걸린 시간)을 DB에 기록해 다른 유저와 순위 경쟁**하기로 바꿈.
- 퀴즈 위치(나중에): QGIS 점 레이어 `quiz_points`(point_id, category, label) → PostGIS `quiz_point(geom Point 5179, GiST 인덱스)`. 문제와 지점에 같은 category(fire, water, nature, road, facility)를 붙이고, 게임 시작 때 문제 4개와 같은 분류의 지점을 무작위로 짝지어 좌표와 함께 보냄 (row_number + random() 쿼리).
- 캐릭터: LX 마스코트 "랜디"나 닮은 모양은 만들지 않음 (저작권). 대신 도형으로 만든 **오리지널 두 발 거북이**. 공식 캐릭터 파일을 받으면 `player.js`의 `CHARACTER_URL`(.glb) 또는 `CHARACTER_IMAGE`(.png)에 넣으면 교체됨.
- 다른 기관 캐릭터·상표가 있는 사진(예: 화장실 문 캐릭터, 분리수거장 제품 워터마크)은 그대로 따라 그리지 않고 일반적인 모양으로 만듦.
- 데이터는 가능하면 **QGIS에서 조절**하고 코드에 좌표를 직접 넣지 않음.
- 낮·밤 선택(2026-11-18): 시작 화면에서 ☀️ 낮 / 🌙 밤을 고름. `daynight.js`의 `MODES` 설정값으로 하늘색·안개·빛을 바꾸고, 밤에는 별·달이 보이고 캐릭터 손전등(PointLight)이 켜짐. 화면에서는 `game.setTime('day' | 'night')`를 부름. "다시 하기"를 해도 고른 것이 유지됨. 7단계 날씨를 만들 때 이 파일의 빛 조절을 같이 쓰면 됨.
- 가로등(2026-11-18): 새 레이어를 만들지 않고 `facilities` 점에 type `lamp`를 찍음(name은 비워도 됨). `lamps.js`가 기둥·갓·전구를 세우고, 밤 버전에서 전구가 빛나고 바닥에 빛 동그라미가 보임. 진짜 불빛(PointLight)은 계산이 무거워서 4개만 만들어 캐릭터와 가까운 가로등으로 옮겨 가며 씀(`LAMP.maxLights`). 기둥은 통과하지 못함.
- 내보내기 자동화(2026-11-18): `gis/export_geojson.py` (PyQGIS). QGIS 파이썬 콘솔에서 실행하면 camp.gpkg의 모든 레이어를 EPSG:5179, 좌표 정밀도 1, RFC7946 NO로 `public/data/`에 한 번에 내보냄. gpkg는 읽기만 함. 저장하지 않은 레이어가 있으면 내보내지 않고 알려 줌. 원본 사본으로 시험해서 9개 레이어 모두 손으로 내보낸 파일과 똑같이 나오는 것을 확인함. 다음 후보: 데이터 검사(type 오타, 빈 값, 경계 밖 도형)를 같은 스크립트에 붙이기.
- 달리는 자동차(2026-11-18): QGIS 선 레이어 `car_routes`(name, speed km/h, count)를 따라 차가 달림 (`cars.js`). 선의 시작점에서 나타나 끝점에서 사라지고 다시 시작점에서 나오는 방식. "끝에서 되돌아오기"보다 코드가 단순해서(거리를 선 길이로 나눈 나머지만 쓰면 됨) 이 방식을 골랐음. 시작·끝 4m 구간에서는 크기가 서서히 커지고 작아짐. 차 모양은 주차장 차(`makeCar`)를 같이 씀. 차 앞길 8m 안(동선에서 옆으로 2.5m 안)에 캐릭터가 있으면 차가 부드럽게 멈추고, 비키면 다시 달림(`CAR.stopAhead`, `stopSide`, `brake`로 조절). 차 뒤나 옆에 서 있으면 멈추지 않음. 차마다 충돌 상자를 `colliders` 목록에 넣고 매 프레임 차 위치·방향으로 옮겨서, 캐릭터가 차를 통과하지 못함. 차가 캐릭터와 겹친 상태가 되면(옆에서 끼어든 경우) 기존 규칙대로 캐릭터가 빠져나올 수 있음.
- 카라반 모양(2026-11-18): 현장 사진을 참고해 `sites.js`의 `makeCaravan(label)`을 다시 만듦. 밝은 회색 판넬 몸체 + 짙은 큰 창 + 옆 나무 데크와 검은 파고라 + 테이블·의자 + 빨간 번호판. 크기·색은 `CARAVAN` 설정값으로 조절. 번호판 글자는 줄 이름과 순서(`F-12`)로 자동 생성되고, 어느 끝이 도로 쪽인지 몰라서 양쪽 끝벽에 모두 달았음. 데크 위 테이블에는 충돌 상자를 추가함.

## 4. 어린이 퀴즈 (13문제, 매 판 4개)

🔥 마시멜로 화상 B-3 (**항상 출제**), 🏃 캠프파이어 술래잡기 A-3, 🆘 친구가 물에 빠짐 (개울 0.3), 🦺 혼자 물놀이 (개울 0.7), ⛲ 바닥분수에서 뛰기 (fountain), 🐍 풀숲 뱀 D-2, 🐝 벌 (playground 없으면 C-1), 🍄 버섯·열매 (개울 0.1), 🐿️ 다람쥐 먹이 (개울 0.9), 🚗 주차장 P-5, 🔦 밤길 텐트 줄 C-2, ⚽ 도로 공놀이 (road 3), 🧭 가족 잃어버림 (office)

추후 추가 후보: 옷에 불(멈춰·엎드려·굴러), 텐트 화재, 라이터, 젖은 바위, 천둥번개, 폭염, 저체온, 장작 패기, 그네, 모르는 어른, 숲길 길 잃음(국가지점번호), 친구 부상 등.

## 5. QGIS 데이터 (gis/camp.gpkg, EPSG:5179)

- 내보내기: GeoJSON, EPSG:5179, COORDINATE_PRECISION 1, RFC7946 NO, 레이어 메타데이터 유지 해제, 같은 이름이면 **파일 덮어쓰기**. (gpkg에 새 레이어를 만들 때는 반드시 "레이어 추가", 덮어쓰기 금지)
- QGIS 입력창에서 한글·긴 글자가 잘 안 들어가는 문제가 있었음 → 필드 길이를 20 이상으로 만들 것. 예전 roads(선)는 name이 1글자 제한이라 숫자 1~5를 씀.
- 레이어 목록과 type 값은 CLAUDE.md 참고. 요약:
  - boundary(경계), roads(폴리곤, 공놀이 퀴즈용 name 3), areas(plaza, parking, fountain, splash, forest, small_tree, road), buildings(office, shower, shower_toilet, toilet, recicle, recicle_toilet, water, car), sites(deck/caravan/parking, name `B-3`), site_rows(선: A4, B8, C6, D3, F13 카라반, P10 주차), river(bed, water), stream(개울 선), facilities(예전 점 방식)
- 고리 모양 도로는 가운데가 구멍인 폴리곤으로 저장됨 → 코드가 구멍을 지원함.

## 6. 코드에서 해결한 문제들 (같은 실수 반복 금지)

- 강바닥을 파면 캠핑장 가장자리 도로가 꺼짐 → 캠핑장 안은 `heightAt`이 항상 바닥 높이를 돌려주게 함 (30m 보호 둑 방식은 강 위에 잔디 둑이 튀어나와서 폐기).
- 주차칸 선이 잔디 아래 묻힘 → 높이 순서: 잔디 +0.1, 바닥 영역 +0.17, 도로 +0.25, 주차칸 +0.3.
- 고리 도로 가운데가 아스팔트로 채워짐 → 폴리곤 구멍(holes) 지원.
- 데크가 도로 모서리 짧은 변 방향으로 돌아감 → 도로 테두리를 따라 앞뒤 8m 이은 방향 사용(`EDGE_SPAN`), 같은 줄에서 혼자 12° 넘게 돌아간 데크는 이웃에 맞춤(`straightenRow`).
- buildings를 쓰면 facilities의 같은 종류 점은 무시 (예전 상자 건물 겹침 방지).
- 건물 안에 찍힌 퀴즈는 건물 앞마당으로, 캠핑장 밖 퀴즈는 경계 안쪽 3m로 옮김.
- DB 문제를 못 받으면 예비 missions.json 사용.

## 7. 코드 점검에서 나온 할 일 (2026-11-17 모두 고침)

1. ✅ 선택 파일: `boundary`만 필수(`loadGeo`), roads·stream·site_rows·facilities 등 나머지는 모두 선택(`loadGeoOptional`). 필수 파일을 못 읽으면 화면에 "캠핑장을 불러오지 못했어요"가 나와요 (`onError`).
2. ✅ 창·탭을 벗어나면(window blur, visibilitychange) 눌린 키를 모두 지워요.
3. ✅ 시작 위치: 기준점에서 건물·나무·텐트와 1.5m, 퀴즈 지점과 8m 떨어진 빈자리를 찾아요(`findStart`). 기준점은 QGIS facilities에 **type `start`** 점이 있으면 그 점, 없으면 캠핑장 가운데.
   - 카메라: 앞 방향을 카메라가 "보는 방향"이 아니라 "도는 각도"(`getAzimuthalAngle`)로 계산 + 바로 위까지는 못 올라가게(`minPolarAngle`).
   - ~~클릭 이동~~: 2026-11-20에 없앴어요. 이동은 키보드(WASD·방향키)로만 해요. 휴대폰에서는 지금 움직일 방법이 없어요.
4. ✅ "다시 하기"는 3D를 다시 만들지 않고 문제와 캐릭터만 새로 준비(`scene.restart()` → `newRound()`). 지난 문제의 고리·아이콘은 `disposeTree`로 메모리 정리. 화면을 떠날 때는 장면 전체를 정리.
5. ✅ 같은 색 재질(`mat`, `flatMat`), 같은 type 바닥 재질(`areaMaterial`), 같은 줄무늬(`stripeTexture`)는 한 번만 만들어 재사용.
6. ✅ 중복 함수는 `geo.js`로 모음: `pointInRing`, `distToSegs/distToRing/nearestOnSegs`, `pointAlong`, `hitsCollider(x, z, colliders, margin)`, `centroid`, `openRing`, 파일 읽기.
7. ✅ 안 쓰는 코드 삭제: 선 도로(ROAD_WIDTH, extendEnds, nearestRoad), FACILITY의 건물 상자와 그 충돌 상자, ALIGN_TYPES, nearestLineAngle. **roads 레이어는 이제 폴리곤만** 읽어요(선이면 경고 후 건너뜀). facilities 점은 `fountain`, `deck`, `start`만 의미가 있어요.
8. ✅ campsite.js(1,449줄 → 약 240줄)를 나눔: `geo.js`(도형 계산·파일 읽기), `shapes.js`(재질·상자·무늬·면·입체), `ground.js`(바닥·도로·바닥분수), `river.js`(강), `buildings.js`(건물), `sites.js`(데크·카라반·주차칸·도로 붙이기·충돌 상자), `trees.js`(나무). campsite.js는 순서대로 배치만 해요.

확인한 것: `npm run build` 통과, 브라우저에서 시작·걷기·창 전환 시 멈춤·다시 하기(약 3ms)·파일 4개가 없어도 시작됨.
남은 메모: 도로 퀴즈(`{"road":"3"}`)는 도로 가운데가 아니라 도로 **테두리 위**의 점에 놓여요 (예전부터 그랬음. 퀴즈 지점을 PostGIS 점으로 옮길 때 같이 해결).
